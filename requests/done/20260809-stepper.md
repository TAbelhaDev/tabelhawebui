# Stepper

> Indicador de progresso visual pra wizards/fluxos multi-etapa. **Já existe no
> tabelawebui desde 0.4.0** (absorção PrimeNG, tier 2); este request foi
> aberto sem checar o componente — reconciliado com a API real e concluído.

- **autor**: tabelafin
- **data**: 2026-08-09
- **prioridade**: medium
- **status**: concluído (componente já existia; API divergente não adotada)

## O que

Componente `Stepper` que mostra a posição do usuário dentro de um fluxo de
N etapas. O request original propôs `steps`/`current`/`variant`, mas o
componente já publicado usa **`items`/`value` bindable** (mesmo padrão do
`Tabs`), só com o visual `numbered`.

## API real (o que está publicado)

```svelte
<Stepper
	items={[
		{ value: 'ai', label: 'IA' },
		{ value: 'pluggy', label: 'Open Finance' }
	]}
	bind:value
/>
```

**Props:**

- `items` (`{ value: string; label: string; disabled?: boolean }[]`, required)
- `value` (string, bindable) — passo atual
- `class` (string, default `''`)

**Comportamento:** passo atual e anteriores com número em destaque (accent);
passos concluídos mostram `✓`; `disabled` bloqueia o clique; `aria-current="step"`
no passo atual.

## Por que / contexto

O wizard de boas-vindas do tabelafin (onboarding IA + Open Finance) tem 2
etapas e precisava de um stepper. Sem ele, cada app montaria um indicador
manual com HTML/CSS paralelo.

## Decisão (API não adotada do spec original)

- `items`/`value` **fica** — consistente com `Tabs` e já publicado; trocar pra
  `steps`/`current`/`variant` seria breaking change sem ganho.
- `variant` (`dots`/`line`) **não foi adotado** — só o `numbered` existe hoje;
  adicionar variantes só se um app pedir de verdade (novo request).
- `aria-current="step"` **adicionado** ao reconciliar (único critério de a11y
  que o componente não cumpria).
